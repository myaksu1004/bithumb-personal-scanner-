# 코인 저점 상승 탐색기 v5.2.2

## v5.2.2 변경 사항 (2026-11-13)
- **백테스트 웹 화면 추가**: `탐색기주소/backtest`. 폰·패드·PC 브라우저에서 종목(최대 5개)·기간(7/14/30일)·수수료를 넣고 실행. 계산은 `backtest.py`를 그대로 불러 쓰므로 PC에서 돌린 결과와 같음. 파일: `backtest_web.py`.
- **단기 반등 태그 5종 추가(관찰용)**: 과매도 복귀, RSI 상승 다이버전스, 투매 후 반전, 저점 스윕 후 회복, 단기 이평 리클레임. 확정 15분봉 기준. 탐색 카드에 초록색 태그로 표시되고, 백테스트에 태그별 이후 4시간/24시간 평균 등락률 표가 나옴. **판정·진입·손절 계산에는 반영되지 않음.** 기준값은 `strategy_config.json`의 `rebound`.
- **오류 수정**: 4시간봉이 180개 미만인 종목에서 180선 비교 때 분석이 멈추던 문제. 해당 구간은 180선 가점 없이 분석을 계속함. 그동안 실시간 탐색에서 조용히 빠지던 종목이 목록에 나올 수 있음.
- 기존 B형 판정·점수·진입·손절은 v5.2와 동일(가상 캔들 8,400개 비교에서 차이 없음).

## v5.2 변경 사항
- **RSI를 Wilder 방식으로 변경**: 거래소 차트의 RSI와 같은 계산법. v5.1보다 값이 완만하게 움직이므로 RSI 조건(42\~68, 과열 75 등)에 걸리는 종목이 달라질 수 있음.
- **타이밍 점수의 RSI 범위를 설정 파일로 연결**: 코드에 박혀 있던 43\~68 대신 `entry.rsi_min`/`rsi_max`(42\~68)를 사용.
- **현재가와 분석 기준가 차이 표시**: 진입·손절 계획은 마지막 확정 15분봉 종가 기준. 실시간 현재가가 `risk.max_entry_slippage_pct`(0.5%) 넘게 벗어나면 경고를 띄우고 'B형 진입 검토'를 'B형 관찰'로 낮춤.
- **설정 연결**: `structure.pivot_left`/`pivot_right`/`min_higher_lows`가 실제로 코드에 반영됨(값이 같아 결과는 동일).
- **미사용 설정 분리**: 코드가 읽지 않던 10개 값은 `strategy_config.json`의 `_not_yet_used`로 옮겨 보존. 이 값들은 바꿔도 결과가 변하지 않음.
- **백테스트 스크립트 추가**: `backtest.py`.

## 전략 요약 (v5.1과 동일)
- B형(4시간봉 확정 저점 상승) 주력, A/C형은 보조 관찰.
- 매도 압력 0~100 별도 표시: 24시간 하락률, 최근 고점 하락률, 음봉 RVOL, MACD/RSI, 연속 음봉.
- 급락+거래대금 급증 등 조건에서는 B형 구조가 살아 있어도 진입 보류.
- 손절은 실제 확인된 지지 아래 버퍼. 손절폭이 너무 넓거나 ATR 대비 너무 좁으면 신규 진입 보류.
- 목표가는 확인된 저항선 기준. 매수 자동 실행 없음. 점수는 수익 확률이 아님.

## 백테스트
### 웹 화면 (폰·패드·PC)
`탐색기주소/backtest`에서 실행합니다. 탐색기 첫 화면의 "백테스트 화면 열기" 링크로도 들어갈 수 있습니다.
- 종목당 1~2분 걸림(Render 무료 서버 기준, 30일). 진행 중에는 화면을 열어 둘 것.
- 결과는 서버 메모리에만 있어 서버가 재시작되면 사라짐. 필요한 결과는 캡처로 보관.
- 한 번에 하나의 백테스트만 실행됨.

### PC에서 직접 실행
파이썬 설치 후 이 폴더에서:

```
pip install -r requirements.txt
python backtest.py --top 10 --days 30
python backtest.py --markets ONDO,BTC,ETH --days 30 --fee 0.04
```

- 과거 15분봉마다 `app.py`의 판정 로직을 그대로 다시 돌리고, 'B형 진입 검토'가 뜨면 다음 봉 시가 진입 → 구조 손절 또는 1차 목표에서 청산한 것으로 계산.
- 출력: 판정별 빈도와 이후 4시간/24시간 평균 등락률, 승률·평균 R·손익비·최대 연속 손실, 거래 내역 `backtest_trades.csv`(엑셀에서 열림).
- 주요 옵션: `--fee` 편도 수수료 %(본인 계정 수수료율로 지정), `--max-hold` 최대 보유 봉 수(기본 192 = 2일), `--entry-wait` 돌파형 진입 대기 봉 수(기본 4), `--no-cache`.
- 10개 종목 × 30일 기준 수 분 걸림. 받은 캔들은 `bt_cache/`에 하루 동안 저장되어, 설정값을 바꿔 다시 돌릴 때는 계산만 다시 함.
- 실시간과 다른 점: 호가·체결강도는 과거 데이터가 없어 중립값 처리, 24시간 등락률·거래대금은 캔들로 근사, '거래대금 상위 55 → 24개' 선별은 재현하지 않음, 같은 봉에서 손절과 목표가 모두 닿으면 손절 처리, 수수료 외 슬리피지 미반영.
- `--top`은 "지금" 거래대금 상위 종목을 과거에 적용하므로 결과가 실제보다 좋게 나올 수 있음. 거래 수가 30건 미만이면 방향만 참고.

## 주의
- 빗썸에서는 탐색·웹 백테스트가 실제 데이터로 동작하는 것을 확인했습니다(2026-11-13). 업비트와 v5.2.2 오류 수정은 가상 캔들로만 검증했으므로 배포 후 확인이 필요합니다.
- 반등 태그의 기준값은 출발점일 뿐 검증된 값이 아닙니다. 백테스트에서 횟수 30회 이상, 'B형 반등 대기'보다 뚜렷이 좋은 결과가 쌓이기 전에는 진입 근거로 쓰지 않습니다.
- Render 무료 플랜에서 속도 제한/타임아웃이 발생할 수 있습니다.
- 스캔은 거래대금 상위 일부 종목만 분석하며, 7일 추적용 영구 저장소는 아직 없습니다.
- Risk/Pressure 점수는 휴리스틱이며 손실 가능성이나 실제 체결가를 보장하지 않습니다. 백테스트 결과도 미래 수익을 보장하지 않습니다.
